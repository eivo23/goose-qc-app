# מערכת בקרת ליקוט אווז 🪿

מערכת אינטרנטית (PWA) המחליפה את קבוצת הוואטסאפ: המלקט מצלם את הקרטונים, והמערכת קוראת בעצמה את **המדבקה הכחולה** (מה שהוזמן) ואת **תווית היצרן** (מה שיש בקרטון), משווה ביניהן, ומתריעה מיד על טעות ליקוט או חוסר ודאות. בעברית, מימין לשמאל, מותאם לאייפון.

התחלת עבודה **ללא קטלוג מוצרים מוגדר מראש** — ההשוואה נעשית ישירות בין שתי התוויות בכל תמונה, והמערכת בונה מילון פנימי בהדרגה מאישורי המנהל.

## דרישות מוקדמות
- Node.js 18.18+ (מומלץ 20+)
- חשבון [Supabase](https://supabase.com) חינמי (בסיס נתונים + אחסון תמונות)
- אופציונלי בשלב ראשון: מפתח [OpenAI](https://platform.openai.com) לזיהוי אמיתי

## התקנה מהירה
```bash
npm install
cp .env.example .env.local     # מלאו את הערכים (ראו בהמשך)
# הריצו ב-Supabase: schema.sql + storage.sql + seed.sql (ראו "הקמת בסיס הנתונים")
npm run dev                    # http://localhost:3000
```

התחברות ראשונית לאחר seed:
- **מנהל:** `manager` / `manager123`
- **מלקט:** `picker` / `picker123`

> אם `npm run dev` עולה ללא Supabase מוגדר — המסכים ייטענו, אך פעולות שמירה ידרשו את משתני ה-Supabase.

## היכן מכניסים כל מפתח API
כל המפתחות נכנסים לקובץ **`.env.local`** בלבד (לא נכנס ל-Git, לא נחשף בדפדפן). ראו `.env.example` לתבנית מלאה.

| משתנה | מהיכן להשיג | שרת/לקוח |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Project Settings → API → Project URL | לקוח+שרת |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase → API → anon public | לקוח+שרת |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → API → service_role | **שרת בלבד** |
| `OPENAI_API_KEY` | platform.openai.com → API Keys | **שרת בלבד** |
| `OPENAI_VISION_MODEL` | למשל `gpt-4o` | שרת |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | `npm run generate:vapid` | שרת |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | זהה ל-VAPID_PUBLIC_KEY | לקוח |
| `AUTH_SECRET` | מחרוזת אקראית ארוכה (לחתימת סשן) | שרת |
| `CONFIDENCE_OK` / `CONFIDENCE_REVIEW` | ספי ברירת מחדל (90 / 75) | שרת |

> כלל: כל מפתח שמתחיל ב-`NEXT_PUBLIC_` נחשף לדפדפן — לכן מפתחות רגישים (service role, OpenAI, VAPID private) **לעולם** אינם עם קידומת זו. כל קריאות ה-OCR/AI מתבצעות בשרת בלבד.

## הקמת בסיס הנתונים
1. צרו פרויקט חדש ב-Supabase.
2. פתחו **SQL Editor** והריצו את `supabase/schema.sql` (טבלאות + RLS + הגדרות).
3. הריצו את `supabase/storage.sql` (יוצר bucket פרטי `carton-images`).
4. הריצו את `supabase/seed.sql` (יוצר משתמש מנהל + מלקט). *(חלופה מקומית: `npm run seed`.)*
5. העתיקו את שלושת מפתחות ה-Supabase ל-`.env.local` / למשתני הסביבה ב-Vercel.

## זיהוי (OpenAI Vision)
המערכת שולחת כל תמונה ל-OpenAI Vision, שקורא את שתי התוויות, מתרגם הונגרית→עברית, מנרמל ומחזיר JSON מובנה. חובה להגדיר:
```
OPENAI_API_KEY=sk-...
OPENAI_VISION_MODEL=gpt-4o
```
בלי מפתח, יצירת בדיקה תחזיר שגיאה ברורה. אין מצב Demo/Sample — כל בדיקה היא אמיתית.

**למה Vision-LLM?** התוויות בעברית/אנגלית/הונגרית דורשות **הבנה** (תרגום, נרמול סמנטי, זיהוי שזהות המוצר שונה למרות מילים משותפות), לא רק קריאת טקסט. הקוד בנוי מאחורי ממשק `VisionProvider` (`src/lib/vision/`) כך שניתן בעתיד להחליף ספק בלי לגעת בלוגיקת ההשוואה.

## התראות Push
1. הריצו `npm run generate:vapid` והדביקו את הפלט ל-`.env.local`.
2. הפעילו מחדש.
3. באייפון: פתחו את האתר ב-Safari → כפתור שיתוף → "הוסף למסך הבית" → פתחו מסמל מסך הבית → הגדרות → "הפעל התראות".
4. מעתה, חריגה בביטחון גבוה תשלח התראה: *"חריגת ליקוט חדשה. לקוח: … הוזמן: … זוהה בקרטון: …"*. לחיצה פותחת את החריגה.

בפיתוח מקומי ללא VAPID — המערכת מציגה את החריגות במסך החריגות עם מונה, ללא Push.

## פריסה לענן
מומלץ **Vercel** (חינם למפעל קטן):
1. העלו את הקוד ל-GitHub.
2. ב-Vercel: New Project → ייבוא הריפו.
3. הוסיפו את **כל** משתני הסביבה מ-`.env.local` תחת Project → Settings → Environment Variables.
4. Deploy. ה-PWA יעבוד ישירות מהדפדפן באייפון (חובה HTTPS — Vercel מספק אוטומטית, נדרש ל-Push).

Supabase כבר בענן. גיבוי DB: Supabase → Database → Backups.

## מבנה הפרויקט
```
src/
  app/
    page.tsx                 התחברות
    picker/                  אזור מלקט (צילום, העלאה, הבדיקות שלי)
    manager/                 דשבורד + רשימת בדיקות + הגדרות
    manager/checks/[id]/     כרטיס בדיקה מלא (תמונות, OCR, תרגום, נרמול, פעולות)
    exceptions/              מסך חריגות
    demo/                    הרצת שתי תמונות הדוגמה
    api/                     כל ה-Backend (auth, checks, exceptions, dashboard, export, push, settings)
  lib/
    dictionary.ts            מונחון תרגום/נרמול רב-לשוני
    normalize.ts             חילוץ זהות מוצר מנורמלת מטקסט
    compare.ts               עקרון הליבה: השוואת מוצרים
    analyze.ts               תזמור בדיקה שלמה + חריגות ברמת הבדיקה
    vision/                  שכבת הפשטה: provider + openai + sample
    db.ts                    שכבת נתונים (שמירה, שאילתות, למידה, דשבורד)
    auth.ts / storage.ts / push.ts / logger.ts
supabase/                    schema.sql + storage.sql
scripts/                     seed.ts + generate-vapid.ts
tests/                       בדיקות מנוע
```

## אבטחה
- כל משתמש מתחבר; סיסמאות ב-scrypt; סשן בעוגייה חתומה httpOnly.
- הפרדת הרשאות: מלקט רואה רק את שלו, מנהל רואה הכול (נאכף ב-API + RLS כרשת ביטחון).
- כל קריאות ה-OCR/AI ומפתחות רגישים בשרת בלבד; שום מפתח לא בדפדפן.
- תמונות ב-bucket פרטי; צפייה רק דרך קישורים חתומים קצרי-תוקף (5 דק').
- **התמונה המקורית ותוצאת המערכת המקורית לעולם אינן נמחקות/נדרסות** — גם אם המנהל שינה את ההחלטה (נשמר בנפרד ב-`ai_original_result`). כל שינוי נרשם ב-`audit_log`.
- ניתן להשבית משתמש (`active=false`).
